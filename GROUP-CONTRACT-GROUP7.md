## Section 1: Terms and Conditions

### 1. Group Allocation

All four of us have agreed to put in equal effort across both
assessments. We track contributions through GitHub commits and
pull requests. If someone does significantly less work than
others, we will raise this with the lecturer and use GitHub
history as evidence.

### 2. Communication

We communicate through Microsoft Teams and use GitHub for
task tracking. Everyone is expected to reply within 24 hours
so work does not stall. We check in every few days to go over
progress and sort out blockers early.

### 3. Task Ownership

Each person is responsible for their assigned tasks. If
something cannot be finished on time, the person needs to
let the group know as early as possible so we can decide
whether to help or reassign. Repeated missed tasks without
notice will be reflected in how marks are distributed.

### 4. Different Schedules

We all have different timetables and commitments outside uni.
We try to plan ahead and be realistic about deadlines. If
someone is struggling, we help out rather than leaving it.

### 5. Conflict Resolution

If we disagree on a decision, we talk it through on Teams
and try to find something everyone is okay with. If we
genuinely cannot agree, we ask the lecturer to help.

### 6. Academic Integrity and AI Tools

We follow CDU academic integrity rules. AI tools like Claude
and GitHub Copilot are permitted in this unit and we use them.
Our ground rules:

- Anyone using AI to generate code reads and understands it
  before pushing to GitHub
- Every decision assisted by AI is documented in the ADR with
  an explanation of why that choice was made
- Every group member can explain any part of the project if
  asked in the viva
- Nobody submits something they cannot explain

We treat AI as a tool to help us work faster, not a replacement
for understanding the work.
